# v4.11：计分试验和真实竞争记录

本轮只做这两项。保留 v4.10 的取图、局部分析和提速、入选前滑动核对、最多 15 张及自适应停止，没有增加满额后的替换复审或新图像处理。

## 两种计分

默认 **新增权重（现有）**：把当前尚未覆盖的图像内容权重相加。

可选 **新增比例（试验）**：用本帧尚未覆盖的可靠前景权重，除以本帧可见的全部可靠前景权重。区域组多不再直接叠加排序首项；同样全部新增的一个组与多个组都得到比例 1。这里的前景包括现有局部和整页内容记录，不包含背景及权重为零的未确认内容。没有可靠前景时比例为 0；原候选资格仍按是否有正权重新增内容判断，背景可以保留原资格，但不会被当作完全新增的局部内容。

仅替换最终排序的第一项。比例相同后，仍沿用原展示范围、裁切、清晰度、偏移、与已选画面差异、停留、时间等排序。因此不能认为它已经理解“独立设置更重要”，也不能保证简单归一化就能解决所有挤占名额的问题。

API 开始请求支持 `experiment_selection_scoring`：`content_weight` 或 `new_content_ratio`。未指定时沿用本次保存的选择，缺失时默认新增权重。实际方法保存到批次算法覆盖参数、每题有效配置和 selection.scoring，base 不接收此覆盖。复制运行保留所选计分方式，旧记录缺失时回到默认；输出上限仍按现有规则默认 15。

## 为什么保留为可选试验

先在本地 `0831_human_v1` 的固定候选和局部特征上试验，不重新取图或重跑局部分析。纯比例改变了五题中的三题名单，其余两题相同。complex_039 两条原来各占三张的允许压缩范围变为各五张；complex_018 标注范围仍占七张。部分范围重叠，不能将它们的数量直接相加。

这不是关键帧质量通过：本地标注主要是允许压缩的范围，没有完整的必须保留帧答案，也不能把未标注帧当成无用图。额外试过裁切优先等同分调整，但也造成明显名单变化，本轮没有把这些附加策略接入。默认保留原评分，比例模式供服务器内部样本验证。

## 竞争记录

每次挑选下一候选时，复用已经计算的排名，为仍在竞争的候选保留最后一次同轮记录：

- 第几轮，竞争第几个名额。
- 本帧和实际优先处理图的同轮分数、前景新增比例、原权重及内容组数。
- 排序首先出现差别的依据，例如新增权重，或同分后的展示范围。
- 优先图随后入选、确认重复还是替换已有代表。

记录使用当轮入选前的覆盖状态，不用最终覆盖状态倒算当时分数。最终仍未覆盖多少另行记录，二者可能不同。优先图不是最终名单中唯一导致本帧落选的图片；这也不是做了一次最终名单替换试验。

旧版达到上限时关联的是按时间排序的最后一张，新版改为本帧最后参与竞争时的实际优先图。首尾已占满上限等未进入竞争的情况，不虚构对手。旧结果不重写，缺少竞争信息时提示旧版未记录。

全部逻辑仍在独立 media.py 内，不读取实验台日志做决策；没有记录器时不保留逐候选竞争记录。关闭滑动检查同样复用这一计分和记录路径。

## 耗时与验证

固定五题，交错运行冻结 v4.10 与新增记录后的默认评分，核对最终帧号、滑动比较次数均一致。包含最终竞争记录写盘的选图阶段平均为 1.369 / 1.361 秒，比例模式为 1.252 秒。单轮波动不能作为提速结论，但本轮未观察到明显增加。该测量不包含前段抽帧和局部分析。

记录使 JSON 增大，本轮选图对照平均约 180KB→316KB；只保留每候选最后一次竞争，没有保存所有候选所有轮次的完整表，也没有增加图像比较、补选或满额后复审。

测试覆盖区域组数量的累加优势、背景不冒充新前景、同轮分数、时间末帧不冒充对手、仅首尾已满、记录开关不改变选择/比较次数、默认及历史重跑、API 参数到实际配置的传递。原设置弹窗、完整卡片和自适应回归继续运行。

## 在原页面试跑

更新代码并重启服务。在同一份输入上分别“新建一次重跑”，选择“只跑实验链路”：一次用默认新增权重，一次选新增比例。它们是两个独立运行，base 仍是固定原版，不等于 v4.10 的实验评分对照。

结果中点击关键帧，再看“按新增内容自适应选图”的处理记录。新版会直接显示双方比较表，可以点击当轮优先图继续追查。建议同时反馈必须保留帧是否恢复、有哪些原本有用的帧消失，以及整体耗时；不需要提供内部视频或图片。
