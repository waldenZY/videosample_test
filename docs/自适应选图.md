# 自适应选图：实验版 v4.5

2026-11-13。默认按识别到的不同内容选图，最多 15 张，不设置最低目标张数，不按视频时长给任务硬分档。保留首尾位置，因此静态视频也可能输出两张。简单约 3–5、中等约 6–10、复杂才接近 15 是验收参考，不是分档规则。

## 更新与运行

在 moto 环境执行 `python -m pip install -r requirements.txt`，安装新增的 OpenCV 无界面版依赖。Pandas 最低版本同步提高到 2.2.2，以兼容 OpenCV 依赖的 NumPy 版本。启动命令仍为原来的一条 Python 命令，无需模型、GPU、OCR、外部服务或前端构建。

新任务默认“自适应，最多 15 张”。旧结果保持原样；从任意旧记录新建重跑，默认使用新版本和 15 张上限。启动 API 仍接受显式 5 / 10，但它们只是更小的自适应上限，不再代表固定填满该张数。base 文件、参数和独立运行能力保持原样。

## 处理过程

1. 固定采样改为每秒 3 帧（约 0.33 秒间隔）；变化取图、时间范围、页面/内容合并规则保留。场景变化仍可额外产生候选，不保证总采样数量恰好减少四分之一。候选读取、特征计算及过程复制继续使用计算复用和有界并行。
2. v4.3 删除“复核前段相近内容”及补回逻辑。“合并重复内容”的输出直接交给局部检查，后续每一步的输出均为输入的子集，不再读取前段已淘汰图片来补充候选。
3. 新增“检查局部内容与代表图”。颜色块与矩形轮廓提供关注区域；没有可靠区域时检查整页。用有纹理的小条进行模板匹配估计位移，再用严格差异条件检查整个重叠区域。
4. 同一内容移动时，内部仅扩展已经观察到的显示范围，不改写已有参考像素。按可见内容、裁切线索、同一区域清晰程度等挑代表；同组能用一张更充分的图展示时替换，不直接多加一张。不同内容和上下互补范围可分别参与最终选择。
5. “按新增内容自适应选图”从同一候选池选择，首尾共用总上限。不再让新页面独占一轮竞争，也不只因同页已有图片而扣分。
6. 每加入一张就重新计算尚未覆盖的内容。覆盖完成、没有可靠新增或达到上限即停。均匀背景的小幅低对比变化没有新的结构线索时，不借此持续加图。
7. v4.1 删除末尾全局去重，自适应选图即为最终输出。内容去重与覆盖判断继续在前面的代表选择和选图中执行，不增加一个纯转存的替代步骤。

局部分析及选图独立于过程日志，仍在 media.py 内。正常抽帧也使用相同算法；最终迁回 auto_eval 时可以移除实验记录部分。

## 能力边界

- 没有文字识别或任务语义理解。不同设置是按局部视觉内容差异区分，不表示程序理解了设置的业务含义。
- “可能被裁切”依据边界及移动关系，不能证明任意卡片已经完整；无边框内容、强压缩、小字或跟踪失败仍可能出错。
- 前段已经合并或未采到的画面不会被后续重新补回。若关键帧在内容合并前就丢失，应直接检查对应阶段，不能把后续选图当成补救。
- 默认一张代表，确认有互补范围才增加。超过一屏的内容可能需要两张；超过 15 张无法覆盖的内容会明确记录。
- 内容片段按图像区域与可见范围计数，不等同于业务操作或设置项数量。没有以“已覆盖”宣称任务证据绝对完整。

## v4.5：固定布局的统一分析 mask

按最新要求暂时假定所有视频使用同一录屏布局。`KeyframeConfig.analysis_mask_box=(.63, .005, .74, .040)` 表示按图片宽高比例计算的左、上、右、下坐标，仅遮挡顶部录屏计时小框；设为 `None` 可关闭。修改配置后重启并新建重跑，实际值记录在每题 `final/keyframes.json` 的 `config` 中。不同布局或没有录屏状态栏的纯画布应关闭或调整该框。

mask 在 FFmpeg 变化检测的分析流、所有灰度/布局/外壳/彩色内容特征、局部代表分析中一致使用。只填充分析副本，不修改取出的候选图片或最终图片。特征在线程间正确传递本题设置，完成或失败后释放，不污染并行任务。不重新识别计时位置，不恢复复杂滚动检查，不增加新的候选步骤。

本轮默认仍为 3fps、最多 15 张，无中间补帧。本轮不调整背景的 0.15 权重、是否继续选图的停止条件、同分排序或首尾保留；这些需另行验证。

完整回归 97 项通过，覆盖所有特征入口、并行预热时的配置传递、关闭 mask、框外按钮差异、原始文件及最终输出保持原样。无状态栏的纯画布测试显式关闭固定布局 mask，不声称它适用于任意画面。已授权本机样本单次为初始 54 张、最终 15 张，含过程记录约 3.52 秒；与此前约 3.50 秒的单次测量接近，不能据此保证其他机器耗时。

## v4.4：撤掉新增检查，固定采样改为 3 帧/秒

用户反馈新增检查没有实际收益且增加耗时。本版删除 v4.2 加入的计时掩码、整页正文滚动覆盖分析和追加的小差异复核，以及相关配置字段、日志字段与专用测试，不保留默认关闭的空步骤。此前已有的局部区域比较、代表图选择及自适应上限 15 张继续使用。

`KeyframeConfig.sample_fps`、`extract_scene_keyframes` 和 `video_to_frame_urls` 三个入口的默认值均改为 3；平台调用也使用该默认值。base 固定版本不变。每题 `final/keyframes.json` 的 `config.sample_fps` 可核实实际采样频率。

新链路继续为内容合并 → 原有局部检查与代表选择 → 自适应选图。无中间补帧，无末尾全局去重，不通过修改名额竞争策略来配合降低采样率。采样变稀可能影响短暂画面是否进入候选，需要按新结果复测，不沿用旧版关键帧完整覆盖或耗时结论。

v4.4 完整回归 91 项通过，包括实际采样时间间隔约 1/3 秒、显式 2/3/4fps 短暂画面案例、base 与历史接口。连续三个约 0.3 秒画面的模拟案例在 2fps 时没有采到中间绿色状态，3fps 和 4fps 在此案例均保留；记录这一限制，不以降低质量断言掩盖漏采。

已授权本机样本本次为初始 54 张、内容合并 17 → 局部检查 17 → 最终 15，含过程保存约 3.50 秒。这是单个样本的单次测量，效果由用户按新结果复测。

## v4.3：删除中间补回

按用户要求移除前段误合并复核函数、执行步骤和新结果中的 `merged_content_review` 字段，不保留一个默认关闭的开关。局部小差异比较、录屏计时排除、正文滚动分析继续使用已有候选，不产生新帧。

新链路在内容合并之后依次为：合并重复内容 → 检查局部内容与代表图 → 按新增内容自适应选图。原有首尾位置保留发生在内容合并之前，沿用原规则。旧结果中的“复核”记录保持原样，需要新建重跑才能看到新链路。

下面 v4.2 及更早版本的测试和耗时仅是历史记录。六设置模拟视频曾依靠补回恢复前段漏掉的一项；删除补回后不能继续声称该视频完整覆盖，前段问题需另行直接修正，本轮不改变前段合并规则。

v4.3 完整回归 88 项通过，新增强制验证：内容合并故意丢弃中间画面后，局部检查的输入必须与内容合并输出完全相同，后续输出不能增加任何帧。已授权本机样本实际为内容合并 20 → 局部检查 20 → 最终 15，含过程记录约 9.94 秒；前六步输出和淘汰原因与 v4.2 一致。

## v4.2：计时干扰与正文滚动

- 仅在分析副本上排除已知录屏布局的计时小框，输出图片和前段六步不变。先检查左上红色录屏按钮，再应用右侧计时位置；没有录屏按钮时不套用该位置。不是通用计时识别，也没有屏蔽整个状态栏。
- 参数在 `videosample/media.py` 的 `KeyframeConfig`：`local_recording_timer_mask=True`；`local_recording_timer_box=(.63, .005, .74, .040)` 是相对于图片宽高的左、上、右、下坐标。可关闭或调整，修改默认值后重启并新建重跑。每题 `final/keyframes.json` 的 `config` 保存实际值。网页未新增这些高级配置的输入框。
- `local_scroll_alignment=True` 启用正文滚动检查。复用本次已经解码的候选图片，不重新抽视频。仅对宽至少 480 像素、具有主要界面底色和可分离横向图案的画面启用；低分辨率、持续密集运动或无法确认的画面沿用原局部检查。
- 至少三条图案有共同上下位移且足够多片段通过核对，才建立滚动关系。每条匹配还检查颜色、边缘与闭合结构；仅允许高清移动重绘的小幅像素偏差，不放宽静态设置图片的整体相似阈值。局部严格匹配后，多边缘区域还检查小范围差异，避免小数字被整区域平均稀释。
- 通过核对的正文共享 `s…` 内容编号，未匹配的文字、按钮或互补显示范围继续拥有独立编号。不会因为整页滚动关系就删除所有局部差异；被代表图替换的旧局部编号不再形成虚假的覆盖要求。
- 固定参考不被后续近似图片改写，避免连续小变化串联漂移。最多保留四份原尺寸滚动参考，每组最多 256 个首次观察片段；达到范围后回退原处理。片段比较复用像素，不重复读取候选图片。
- 局部检查详情新增 `ignored_recording_timer`（排除的计时框像素坐标）及 `scroll_comparison`（参考时间、位移、共享片段和独立片段数量）。这些是图像线索，不等同于已理解业务含义。

这轮没有针对首帧与紧随其后的轻微变化做强制删除，也没有恢复末尾全局去重。正文滑动和按钮高亮可能同时发生；无法确认的差异仍保守保留，不能保证所有人眼看来重复的图片都会合并。真实任务仍可能触顶，不能把启用滚动检查等同于已经达到最终张数与质量验收。

## 页面如何查看

- 逐样本展开查看局部检查及自适应选择步骤；替换关系指向使用的代表图。旧版本记录仍按当时的实际步骤展示，历史“复核”步骤不会被抹掉。
- 停止原因区分“已识别的内容已覆盖”“剩余候选没有可靠新增内容”“达到上限仍有内容未覆盖”。最后一种提供未覆盖片段数，并可切到本步未选图片。
- 批次统计显示平均张数、1–5 / 6–10 / 11–14 / 15 张的题数、按停止原因计算的触顶比例，以及平均和最长抽帧用时。
- 触顶按实际停止原因统计；旧版即使最后去重减少张数，仍按原停止原因计入。旧记录缺少停止信息时显示缺失，不按“未触顶”计入。

## 验收与复现

测试覆盖不同设置弹窗、PNG/JPEG/高清半卡到全卡、长卡互补、重复等待、循环位移、同页小变化、低对比背景变化、超限与确定性，以及 base、历史接口、统计和前端渲染。

本轮完整回归 79 项通过；最终实现另与原 v3 对照，六个前段阶段的输出和决定一致，240 张候选图片的内容校验值一致。这个对照只核对前段保持原决定，最终自适应输出按新规则验收。

在 moto 环境运行：

```bash
python -m pytest -q tests
python tools/benchmark_adaptive.py --workers 2
```

固定视频组合包含 60 秒简单任务、120 秒六设置任务、120 秒滚动长卡、120 秒加载位移，以及 120 秒持续动态高清压力视频。视频、过程图片和 JSON 全部在 runs/ 下，不提交输入素材。组合默认与平台一样并行两题；`--workers 1` 可做顺序测量，`--skip-tail` 仅用于快速检查，不能代替完整验收。

合成任务按最终图片与原始画面模板的对应关系检查内容覆盖，不要求固定毫秒命中。压力视频仅检查运行、上限和长尾耗时，不代表有业务关键帧标注。耗时含过程保存、不含视频生成、下载或线程池排队；目标是整批平均约 10 秒，复杂长尾同时报告。

真实样本仍需在服务器上由用户验收，无需提供内部数据。简单、中等任务若普遍触顶，或少图后继续丢失不同设置与完整卡片，则不能仅凭张数下降判定通过。

## 本轮本机结果

在 moto 环境测量，NumPy 2.2.6、Pandas 2.3.3、Pillow 12.3.0、OpenCV headless 4.12.0.88；两题并行，含过程记录。下表为 v4 删除末尾步骤前的完整组合测量，v4.1 未据此宣称额外加速：

| 合成视频 | 输出张数 | 抽帧用时 | 是否因上限停止 |
| --- | ---: | ---: | --- |
| 简单设置，60 秒 | 4 | 2.821 秒 | 否 |
| 六个不同设置，120 秒、720×1280 | 8 | 7.603 秒 | 否 |
| 滚动长卡，120 秒、720×1280 | 4 | 4.972 秒 | 否 |
| 加载位移，120 秒 | 3 | 2.464 秒 | 否 |
| 持续动态压力视频，120 秒、720×1280 | 15 | 22.570 秒 | 是 |

普通四项平均 4.465 秒，包含压力项的五项平均 **8.086 秒**；本次固定组合通过了平均约 10 秒目标。输出平均 6.8 张，五项中仅压力视频因上限停止；这个结果只代表本机合成组合，不代替真实业务验收。

开发过程中的完整组合平均还曾测得 11.1、25.5、32.4、16.5 秒，期间有性能优化且运行波动明显。最终增加粗到细的等价预筛与按 CPU 数限制的独立特征预热后，才得到本次 8.086 秒；历史较慢测量仍保留，不能据单次通过保证服务器稳定达到该速度。各轮原始 JSON 保留在本机 runs/adaptive_acceptance/，生成素材未提交。服务器上的同样输入与真实任务分布仍需复测。

六设置视频曾有一项在原前段被合并，加入经用户确认的前段复核后补回；画面切换时间因编码可能相差一个视频帧，因此验收按实际图片内容而非固定毫秒范围进行。前段计算复用另用 60 秒动态视频核对原 v3 的六个阶段决定及全部候选图片内容一致。
