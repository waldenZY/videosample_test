# 自适应选图：实验版 v4.1

2026-11-13。默认按识别到的不同内容选图，最多 15 张，不设置最低目标张数，不按视频时长给任务硬分档。保留首尾位置，因此静态视频也可能输出两张。简单约 3–5、中等约 6–10、复杂才接近 15 是验收参考，不是分档规则。

## 更新与运行

在 moto 环境执行 `python -m pip install -r requirements.txt`，安装新增的 OpenCV 无界面版依赖。Pandas 最低版本同步提高到 2.2.2，以兼容 OpenCV 依赖的 NumPy 版本。启动命令仍为原来的一条 Python 命令，无需模型、GPU、OCR、外部服务或前端构建。

新任务默认“自适应，最多 15 张”。旧结果保持原样；从任意旧记录新建重跑，默认使用新版本和 15 张上限。启动 API 仍接受显式 5 / 10，但它们只是更小的自适应上限，不再代表固定填满该张数。base 文件、参数和独立运行能力保持原样。

## 处理过程

1. 固定采样、变化取图、时间范围、页面/内容合并的原选择规则保留。候选图片读取、特征计算及过程复制增加计算复用和有界并行，不改变这些步骤的决定。
2. 新增“复核前段相近内容”。用户同意将旁路向前复核：原来被合并的图片若与现有代表存在不同局部内容，可以补回候选；否则仍由已有图片代表。原合并记录不被改写，复核显示为什么补回以及补回数量。时间范围外和原末帧近邻排除的图片不借此绕过原时间规则。
3. 新增“检查局部内容与代表图”。颜色块与矩形轮廓提供关注区域；没有可靠区域时检查整页。用有纹理的小条进行模板匹配估计位移，再用严格差异条件检查整个重叠区域。
4. 同一内容移动时，内部仅扩展已经观察到的显示范围，不改写已有参考像素。按可见内容、裁切线索、同一区域清晰程度等挑代表；同组能用一张更充分的图展示时替换，不直接多加一张。不同内容和上下互补范围可分别参与最终选择。
5. “按新增内容自适应选图”从同一候选池选择，首尾和旁路共用总上限。不再让新页面独占一轮竞争，也不只因同页已有图片而扣分。
6. 每加入一张就重新计算尚未覆盖的内容。覆盖完成、没有可靠新增或达到上限即停。均匀背景的小幅低对比变化没有新的结构线索时，不借此持续加图。
7. v4.1 删除末尾全局去重，自适应选图即为最终输出。内容去重与覆盖判断继续在前面的代表选择和选图中执行，不增加一个纯转存的替代步骤。

旁路及选图独立于过程日志，仍在 media.py 内。正常抽帧也使用相同算法；最终迁回 auto_eval 时可以移除实验记录部分。

## 能力边界

- 没有文字识别或任务语义理解。不同设置是按局部视觉内容差异区分，不表示程序理解了设置的业务含义。
- “可能被裁切”依据边界及移动关系，不能证明任意卡片已经完整；无边框内容、强压缩、小字或跟踪失败仍可能出错。
- 复核使用前段图像特征定位差异，无法保证找回所有极小或未采到的变化。不在候选中的短暂画面不能由选图补救。
- 默认一张代表，确认有互补范围才增加。超过一屏的内容可能需要两张；超过 15 张无法覆盖的内容会明确记录。
- 内容片段按图像区域与可见范围计数，不等同于业务操作或设置项数量。没有以“已覆盖”宣称任务证据绝对完整。

## 页面如何查看

- 逐样本展开后查看新增的复核、局部检查及自适应选择步骤。被补回的图仍保留前面被合并的历史；替换关系指向使用的代表图。
- 停止原因区分“已识别的内容已覆盖”“剩余候选没有可靠新增内容”“达到上限仍有内容未覆盖”。最后一种提供未覆盖片段数，并可切到本步未选图片。
- 批次统计显示平均张数、1–5 / 6–10 / 11–14 / 15 张的题数、按停止原因计算的触顶比例，以及平均和最长抽帧用时。
- 触顶按实际停止原因统计；旧版即使最后去重减少张数，仍按原停止原因计入。旧记录缺少停止信息时显示缺失，不按“未触顶”计入。

## 验收与复现

测试覆盖不同设置弹窗、PNG/JPEG/高清半卡到全卡、长卡互补、重复等待、循环位移、同页小变化、低对比背景变化、超限与确定性，以及 base、历史接口、统计和前端渲染。

本轮完整回归 79 项通过；最终实现另与原 v3 对照，六个前段阶段的输出和决定一致，240 张候选图片的内容校验值一致。这个对照只核对前段保持原决定，最终自适应输出按新规则验收。

在 moto 环境运行：

```bash
python -m pytest -q tests
python tools/benchmark_adaptive.py --workers 2
```

固定视频组合包含 60 秒简单任务、120 秒六设置任务、120 秒滚动长卡、120 秒加载位移，以及 120 秒持续动态高清压力视频。视频、过程图片和 JSON 全部在 runs/ 下，不提交输入素材。组合默认与平台一样并行两题；`--workers 1` 可做顺序测量，`--skip-tail` 仅用于快速检查，不能代替完整验收。

合成任务按最终图片与原始画面模板的对应关系检查内容覆盖，不要求固定毫秒命中。压力视频仅检查运行、上限和长尾耗时，不代表有业务关键帧标注。耗时含过程保存、不含视频生成、下载或线程池排队；目标是整批平均约 10 秒，复杂长尾同时报告。

真实样本仍需在服务器上由用户验收，无需提供内部数据。简单、中等任务若普遍触顶，或少图后继续丢失不同设置与完整卡片，则不能仅凭张数下降判定通过。

## 本轮本机结果

在 moto 环境测量，NumPy 2.2.6、Pandas 2.3.3、Pillow 12.3.0、OpenCV headless 4.12.0.88；两题并行，含过程记录。下表为 v4 删除末尾步骤前的完整组合测量，v4.1 未据此宣称额外加速：

| 合成视频 | 输出张数 | 抽帧用时 | 是否因上限停止 |
| --- | ---: | ---: | --- |
| 简单设置，60 秒 | 4 | 2.821 秒 | 否 |
| 六个不同设置，120 秒、720×1280 | 8 | 7.603 秒 | 否 |
| 滚动长卡，120 秒、720×1280 | 4 | 4.972 秒 | 否 |
| 加载位移，120 秒 | 3 | 2.464 秒 | 否 |
| 持续动态压力视频，120 秒、720×1280 | 15 | 22.570 秒 | 是 |

普通四项平均 4.465 秒，包含压力项的五项平均 **8.086 秒**；本次固定组合通过了平均约 10 秒目标。输出平均 6.8 张，五项中仅压力视频因上限停止；这个结果只代表本机合成组合，不代替真实业务验收。

开发过程中的完整组合平均还曾测得 11.1、25.5、32.4、16.5 秒，期间有性能优化且运行波动明显。最终增加粗到细的等价预筛与按 CPU 数限制的独立特征预热后，才得到本次 8.086 秒；历史较慢测量仍保留，不能据单次通过保证服务器稳定达到该速度。各轮原始 JSON 保留在本机 runs/adaptive_acceptance/，生成素材未提交。服务器上的同样输入与真实任务分布仍需复测。

六设置视频曾有一项在原前段被合并，加入经用户确认的前段复核后补回；画面切换时间因编码可能相差一个视频帧，因此验收按实际图片内容而非固定毫秒范围进行。前段计算复用另用 60 秒动态视频核对原 v3 的六个阶段决定及全部候选图片内容一致。


## v4.1 清理记录

用户补充：剩余漏帧基本发生在达到 15 张之后，应聚焦名额分配，而非继续扩大候选。

删除了末尾全局去重函数、执行步骤及不再适用的“去重前/后”新结果字段，选图结果直接输出。新结果以 selection.selected_count 记录实际张数；界面继续兼容旧记录的 selected_after_dedup 字段和原步骤。严格相似参数仍被前段复核和局部比较使用，不因函数删除而移除。

既有五项合成记录中，该步骤均未删除图片。新版本对简单任务、六设置任务重新抽帧，选中时间点及图片内容校验值均与旧结果一致，仍为 4 张和 8 张。保留复核与局部检查，因为已有救回内容及代表选择的用途；本次没有调整 15 张内的优先级，也不把清理步骤当作漏帧问题已经解决。
