# v4.9 / v4.10 局部搜索提速试验

## 数据与范围

使用本机独立保存的 `data/testsets/0831_human_v1`，包含五题真实视频及 370 张内容合并后的候选。三题有部分人工压缩反馈，两题未人工标注，用于验证；它们不等于完整的关键帧标准答案。未按样本编号、帧号或时间定规则。素材、标注和详细运行记录全部留在 Git 忽略目录中。

这次只改局部区域的位置搜索。采样、候选、前段合并、计时遮挡、RGB 严格核对条件、代表与名额选择、滑动判断及 base 均保留。

## 先试过的简单办法

把图横向缩小，选三个可能位置，再回原图附近搜索；找不准时回退全范围搜索。调试样本输出虽相同，但复杂题约七到八成请求仍回退，收益小，部分情况更慢。这一版没有接入。

## 接入的办法

原搜索把约 24 像素高、接近区域全宽的条带放进参考图里找位置。新搜索先把每行分成 32 块平均，同时保留平均后丢失的变化量；纵向不缩小，仍使用原图行坐标。

依据中心化相关分数，估计每个位置还可能达到多高的分数。如果整个参考都不可能达到原门槛，这次比较可以直接返回“不匹配”；否则保留可能的位置，在原图相应小范围搜索，再执行原来的 RGB 重叠核对。它不理解文字，也不把小图相似当成合并理由。

说明中的“上界”是在精确运算下的投影与残差能量不等式；实现另有浮点余量及低方差保护。不能据此宣称跨所有平台逐位等价，仍要核对位置、内容关系和最终图片。原始相关分数公式见 [OpenCV 模板匹配文档](https://docs.opencv.org/4.13.0/df/dfb/group__imgproc__object.html)。

以下情况走原全范围搜索：

- 区域较小或可搜索范围很短，缩小计算不划算。
- 数值不可靠，或可能位置覆盖过大、过于零散。
- 得分接近原匹配门槛，或多个位置得分过于接近。

低方差窗口保留为不确定，不凭不稳定归一化排除。投影准备最多缓存八张图，每题独立，结束和失败后清理。没有新依赖或额外视频采样。

## 测量与核对

冻结 v4.8 源码，在同一候选集上与 v4.9 对照。每题核对全部内容覆盖、内容权重、质量分数、特征、代表候选、替换关系、区域跟踪位置及最终帧号一致。模板峰值计算的浮点分数允许小差异，不能把时间和计数当作确定性结果。

| 样本 | 候选数 | v4.8 局部秒数 | v4.9 局部秒数 | 原范围回退比例 |
| --- | ---: | ---: | ---: | ---: |
| complex_018 | 17 | 0.92 | 0.74 | 9.7% |
| complex_039 | 89 | 7.62 | 4.93 | 22.0% |
| complex_067 | 65 | 11.99 | 7.45 | 3.9% |
| 设置项1600条-1129 | 19 | 2.66 | 1.71 | 32.2% |
| complex_101 | 180 | 10.65 | 7.59 | 26.8% |

顺序跑题，局部检查平均 **6.77→4.49 秒**，约减少 34%。按平台两题同时跑，平均 **7.43→5.28 秒**，约减少 29%。包含最后选择、从内容候选开始的平均耗时，分别为 8.16→5.74 秒及 8.80→6.64 秒。

这些都不是完整视频抽帧耗时，不包含前段解码、取图和完整过程保存，也不能保证服务器上的一分钟长尾已经解决。本地样本的原选图保持一致，不代表修好了已有的漏帧问题。

测试另覆盖亮色、暗色、低对比、常数背景、重复峰、不同可见高度、不同匹配门槛、缓存上限和失败清理。数值与位置边界通过后，仍需用户用服务器内部样本验证，数据不需要提供出来。

## 平台查看与关闭

更新代码并重启服务，旧批次“新建一次重跑”，选择实验链路。每题原位置新增“小图限制搜索范围”：尝试、无可行位置、原图局部定位、回退、原图全范围调用和局部调用次数。回退比例包含小区域直接沿用原搜索的情况。

“原尺寸图案搜索”包含全范围及局部调用，次数不一定下降；应同时看搜索范围和时间。“搜索位置累计”包含小图计算及原图搜索，内部子项不能重复相加。历史记录缺失不按零解释。需要关闭 v4.9 的位置范围限制时，将 `KeyframeConfig.local_bounded_search` 默认值改为 `False` 后重启。v4.10 的参考预筛由独立开关控制，见后文。

## v4.10：先排除对不上当前区域的参考

继续使用上述五题真实候选，与冻结的 v4.9 源码比较。先测试了相同局部区域和相同参考对结果复用：长题的完全一致区域很少，复杂题一共只有个位数到十余次命中，收益不足以接入。仅在调度前排除宽度不同的参考，收益也很小。

接入的办法是：先计算 RGB 区域每一行的八列面积均值，再用纵向积分检查全部合法重叠位置。先比较整体高度平均，有必要时逐步细分到八段。平均后的差异是原 8×8 粗核对差异的保守下界；原粗核对门槛不变，额外留量化余量。只有所有合法位置均不能通过时，才跳过这个参考的模板搜索。可能位置过多时立即返回“不确定”，继续原搜索。

它不判断两张图相同，不删除任何候选，也不根据人工标注、任务语义或时间删除参考。剩余参考按原顺序判断。宽度不符的项原本就会立即失败，现在只把这一检查提前到线程调度前。

原位严格核对通过时，不再做这项预筛。参考的积分按需准备一次，像素扩展后失效，参考淘汰后清理；活跃参考上限保持 32。当前区域的积分跨该区域的比较复用，后续没有额外全局缓存。scene 灰度的存在性参与弱内容判断，跳过重搜索时仍保留这项原准备行为。

| 样本 | v4.9 局部秒数 | v4.10 局部秒数 | 颜色预筛比较 / 跳过重搜索 |
| --- | ---: | ---: | ---: |
| complex_018 | 0.78 | 0.62 | 26 / 16 |
| complex_039 | 4.93 | 2.84 | 240 / 188 |
| complex_067 | 7.56 | 3.83 | 727 / 580 |
| 设置项1600条-1129 | 1.69 | 0.70 | 30 / 27 |
| complex_101 | 7.45 | 4.56 | 360 / 271 |

顺序跑题，局部平均 **4.48→2.51 秒**，约减少 44%；两题并行 **5.21→3.07 秒**，约减少 41%。包含最后选择、从内容候选开始的平均耗时，分别为 5.92→3.76 秒及 6.60→4.47 秒。全部覆盖、内容权重、质量、特征、代表替换、区域位置及最终帧号均一致；仍不代表完整抽帧已满足服务器耗时目标。

在五题上还执行了只记录、不真正跳过的对照，未发现被排除参考在原算法中能够匹配的情况。回归另外覆盖重叠范围边界、不同宽高、低对比、全部合法位置逐一复核、参考扩展失效，以及 scene 弱内容分类准备行为。

平台每题的“参考快速排除”展示实际颜色预筛次数、跳过重搜索次数、宽度不符的备选项数量及累计用时。宽度预筛会查看全部备选，可能包括原来尚未访问的参考；不能直接与旧版“未匹配次数”相减。累计用时已在局部总耗时内，线程间可能重叠。关闭本轮优化可将 `KeyframeConfig.local_reference_prefilter` 默认设为 `False`，重启后恢复 v4.9 的比较范围。

本轮缩小了重搜索的参考范围，仍然分析全部内容候选，没有实现“只对最后入选的图片做局部分析”，也没有增加前段删帧。
