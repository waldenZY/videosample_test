# 原视频链接、下载副本与批次清理

2026-11-17 平台更新。抽帧算法仍为 v4.13，未修改 `media.py`、固定 base 或选帧参数。

## 原视频入口

样本展开后只保留“打开原视频”链接，无内嵌播放器，也不再提供跳转播放器到某帧的按钮。图片的视频时间点仍保留供手动对照。

- HTTP/HTTPS 输入：新标签页直接打开原地址，不经服务器下载、缓存或转码；需浏览器所在电脑能访问且链接未过期。
- 服务器文件输入：由平台按输入路径读取原文件，以 HTTP 返回；不复制文件、不要求批跑，不依赖 `video_ref.json` 或处理副本。相对路径沿用项目和 `OPERATION_VIDEO_ROOTS` 查找。
- 未开始、未勾选、运行中、失败和已完成样本都可使用。缺文件或非法样本给出明确错误。最终播放还是下载取决于浏览器及编码。
- 删除整批后，其平台文件访问链接失效，但不会因此删除服务器原始文件；远程原地址本身不因批次删除而改变。

## 下载副本保留开关

开始配置新增“保留下载视频”，默认关闭，作用于 base 和实验链路。启动 API 字段为严格布尔值 `retain_downloaded_video`，默认 `false`。每批保存实际设置，顶部和 XLSX 概览显示。

关闭时，同题所有链路都已结束或失败、且后台处理函数不再使用文件后，清理该批 `inputs/<行号>/video.mp4` 和残留 `video.part`。排队中的另一条链路也算未结束，不能仅按当前活跃使用者数删除。两条链路仍只下载一次，共用处理副本；不会因第一条先结束而让另一条重新下载。

开启时保留处理副本。原视频链接仍访问输入来源，不切换为缓存播放；开关与观看入口独立。新建重跑默认重新关闭。历史记录缺少该设置时按旧行为保留，不追溯清理既有下载视频。

只删除工具自己管理的下载位置，不根据输入 `video_path` 或 `video_ref.json` 删除文件。清理失败保留文件并在样本提醒中说明，不把已成功的抽帧改判为失败；下次启动补清理不保留批次的残留文件。清理发生在抽帧结束后，不计入抽帧算法内部耗时。

自动清理仅节省下载视频空间，全部候选图、缩略图和最终图片仍用于实验查看；需要清掉这些占用时使用整批删除。

## 整批删除

批次详情提供“删除整批记录”，确认后调用 `DELETE /api/runs/{id}`。从 base 或实验任一侧删除，都删除同批全部关联记录，包括输入副本、算法快照、候选/缩略/最终图片、过程与统计文件，以及保留的下载视频。不会沿原视频路径删除文件，也不删除独立的新建重跑记录。

仍有排队或运行状态、或后台函数尚未结束时，服务端拒绝删除（409），页面运行中禁用按钮。未开始、已结束和已中断批次可删除。删除后不可恢复，已导出 XLSX 中指向本批结果的图片目录也会失效。

删除前验证所有关联与绝对目标，只操作 `runs` 下严格命名的批次目录；拒绝批次根目录或下载路径通过符号链接/Windows junction 指向别处。递归清理不沿内部目录链接删除外部目标。

先在同一存储目录下将整批目录改名为 `.deleting-<随机编号>`，再移除文件，避免后台记录刷新与删除交错。文件被占用等情况导致未能彻底释放时，接口明确返回清理待完成，下次启动继续清理；不会把临时删除目录重新当成批次列出。沿用原单进程服务模式，不引入数据库或外部队列。

## 验证范围

回归包括：未批跑本地原视频、远程原地址不下载、双链路共用副本、第二条仍在排队、一成一败、保留开关、新建重跑、异常重启补清理、清理失败提醒、整批及子链路入口删除、独立重跑保留、运行任务禁止删除、目录越界拒绝、Windows junction 不误删源目录，以及前端无播放器且直达原始链接。

普通符号链接测试受 Windows 创建权限限制时跳过，另用不需该权限的 Windows junction 验证根目录拒绝与内部链接目标保留。固定 base、实验核心、相似阈值、比例排序和候选规则均未更改；只调整平台文件生命周期和观看入口。

本轮完整回归：253 项通过、1 项普通符号链接创建因系统权限跳过。Windows junction 的批次根目录拒绝、内部链接目标保留、下载目录拒绝三项均实际通过。未启动平台服务，也未清理既有真实批次；删除及恢复验证只作用于独立的测试临时目录。
