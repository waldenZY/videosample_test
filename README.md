# 抽帧实验台

从 auto_eval_agent 的现有抽帧方法开始，查看一批视频在每一步留下和丢弃的画面，帮助判断修改是否保住了重要信息。

仓库：<https://github.com/waldenZY/videosample_test>

## 当前状态

- 已建立本地仓库与远程 main 分支的跟踪配置；远程仓初始化时为空。
- `reference/media.py` 保存当前 auto_eval_agent 抽帧模块的原样副本。
- `reference/source.json` 记录来源、版本与文件校验值。
- 已实现文件上传、批跑、各阶段查看、淘汰原因追踪、相关图片与原视频对照。
- 每次可选只跑 base、只跑实验或两条都跑，查看各自步骤和结果，不做步骤对齐或差异对比。
- 第一版方案见 [docs/方案.md](docs/方案.md)。

原始副本用于核对初始结果。固定 base 不变，实验链路已开始尝试保留快速变化与短暂画面。

输入及抽帧前处理参考 auto_eval_agent，抽帧完成后进入查看页面，不继续评估。固定基线位于 `videosample/versions/base_media.py`，实验修改放在 `videosample/media.py`。定稿迁回时允许少量适配，去掉实验用过程记录与中间图片，保留正常抽帧输出。

## 启动

进入本项目目录，在 moto 环境运行（Python 3.10 或更新版本）：

```bash
conda activate moto
python -m pip install -r requirements.txt
python app.py --host 0.0.0.0 --port 8503
```

本机打开 <http://127.0.0.1:8503>；部署到服务器时，本地浏览器访问 `http://服务器地址:8503`。网页无需另行构建。FFmpeg 可使用系统安装或依赖中的 imageio-ffmpeg，首页会检查是否就绪。

## 使用

1. 上传现有 Excel、CSV 或 JSONL，预览样本、错误与提醒。
2. 勾选样本，选择只跑 base、只跑实验或两条都跑。实验输出默认“自适应，最多 15 张”，不设置最低目标张数；该策略只影响实验链路。新导入默认只跑实验，后台最多同时执行两项抽帧工作。
3. 只跑一条时直接查看该链路；两条都跑时通过链路按钮切换。点击样本就地展开本链路的步骤与图片，详情显示所用链路和版本。
4. 点击图片，查看其处理经过与相关画面；可以定位到原视频相应时刻。
5. 点击“新建一次重跑”复用输入，默认沿用上次运行方式，并采用当前实验版的自适应 15 张上限。旧结果保留原参数与图片；显式 5 / 10 的 API 请求仍可作为更小的自适应上限。
6. 展开样本中的“查看各阶段耗时”，查看视频准备、读取信息、视频内容校验和抽帧处理的耗时；实验链路还会列出取图、内容筛选、名额分配、去重与过程保存的分项。分项属于抽帧合计，不重复相加。旧结果不补造耗时数据，需重跑后查看。
7. “本次链路统计”分别展示各链路的平均每题总用时、平均抽帧用时、初始候选和最终输出的平均张数与总数。仅统计成功样本，不受列表筛选影响；每项 n 是实际有该项数据的题数，旧记录缺失的字段不按零计入。还会显示输出张数分布、真实触顶比例及最长抽帧用时，展开样本可看停止原因。

初始候选数量指第一次筛选前收集的全部候选，含固定采样、场景变化及首尾帧，未去重；不是原视频的总帧数。每题总用时含视频准备与下载等待，不含线程池排队。总张数仅汇总本链路成功样本。

两条链路各自记录步骤，实验链路以后可以增删或重排步骤，不需要与 base 对应。一条链路失败不会阻止另一条完成。

## 固定 base 与后续实验

base 固定为复制时 auto_eval_agent `45dd11a` 的 `hybrid-state-v3.2.0`：选帧方法与默认参数相同，只增加实验用过程记录。本地路径允许读取项目目录外的视频是实验台外围适配，不改变抽帧方法。

`videosample/versions/base_media.py` 与 `base.json` 不再修改。以后在 `videosample/media.py` 中尝试新方法或参数，重启服务后只跑实验即可；需要基线时再选 base 或两条都跑。

当前实验版 `hybrid-state-exp-v4.10`：

- 固定采样从每秒 4 张改为每秒 3 张（间隔约 0.33 秒）；场景变化额外取图、时间范围及前段合并规则保持不变，因此总体候选数量不一定恰好减少四分之一。
- v4.5 按固定录屏布局统一遮挡计时小框：变化检测、布局/内容特征和局部比较都在分析副本上遮挡，过程图及最终图仍为原图。配置为 `analysis_mask_box`，设为 `None` 可关闭；具体位置见使用说明。
- v4.6 在占用最终名额前检查滑动/静止重复，确认重复则更新代表和覆盖记录，再继续选下一候选；保留原局部分析，不使用未通过的新状态分组。每题最多按候选数 3 倍发起比较请求，预算用完后未确认重复的候选仍正常参选。该版本解决执行范围与过程追踪，不保证所有滑动都能识别。
- v4.7 减少局部检查中的重复搜索：等尺寸原位通过严格核对就不再搜索位移；复用同一图像的搜索准备和完全相同输入的搜索结果；最近参考优先，其余最多两个并行并按原顺序决定。采样、候选范围、相似门槛、代表选择和最终选图规则保持不变。
- v4.8 仅补充耗时定位，沿用 v4.7 选图。原页面每题显示“局部耗时细分”和“最慢的 3 张候选图”，批次统计可展开“平均局部开销”。更新并重启服务后，从旧批次“新建一次重跑”；旧结果不变，缺少细分时显示未记录。
- v4.9 大区域搜索先保守缩小可能位置，再在原图这些位置附近搜索，并沿用原严格核对。低对比、临界和重复位置等不确定情况回退原搜索，不删除候选或调整选图权重。每题新增“小图限制搜索范围”、回退比例、原图全范围/局部搜索次数。局部搜索调用可能增多，但单次范围更小，应结合耗时判断。实现与本地真实数据测量见 [局部搜索提速](docs/局部搜索提速.md)。
- v4.10 在重搜索前快速检查区域与参考的颜色分布；只有所有合法上下位移都不可能通过原核对时才跳过该参考。候选图片仍全部参选，沿用原选图。原页面新增“参考快速排除”的检查、跳过及累计耗时；备选参考中宽度不符的项先过滤，数量不等于比旧版少执行的比较次数。`local_reference_prefilter=False` 可关闭本轮预筛，回到 v4.9 的比较范围。
- 原批跑页“平均抽帧用时”下增加局部检查平均耗时、原位匹配和完整搜索平均次数。展开某题即可看到局部检查耗时、输入张数、直接匹配、完整搜索和未匹配次数，“查看搜索开销”还有实际图案搜索、缓存复用和线程上限。一次完整搜索可能包含多个图案；未匹配次数不等于丢帧数。旧记录缺少这些信息时显示未记录，不按零计入。
- 滑动检查沿用已试验的手机录屏布局及原尺寸像素容差；默认候选图小于 400×800 时返回“不确定”，继续原选图，避免细小文字/按钮被固定像素门槛吞掉。相关配置为 `scroll_min_width` / `scroll_min_height`。`scroll_dedup_enabled=False` 可关闭本轮检查；计时 mask 与底部操控指示条分别由 `analysis_mask_box` / `scroll_agent_indicator_box` 配置，仅用于分析，原图不变。
- 每题“按新增内容自适应选图”中可查看滑动比较、代表替换、未检查和达到上限的原因。原图和历史结果不改。更新后重启服务，旧批次选择“新建一次重跑”，运行链路选“只跑实验链路”。
- 整页正文滚动检查和追加的小差异复核继续移除，保留此前已有的局部内容与代表图选择。本次不调整背景权重、停止条件或末尾排序。
- 已删除前段误合并复核和补回步骤，内容合并后只筛选现有候选，不再增加图片。
- 用局部颜色、轮廓、模板匹配及重叠内容检查提供移动与裁切线索。同一内容优先换用展示更充分的代表，只有互补内容才增加图片。
- 取消新页面独占名额与同页扣分。每次只为尚未覆盖的内容增加图片；覆盖完、没有可靠新增或达到上限即停。不同设置和旁路没有额外名额豁免。
- 默认最多 15 张，不设凑数下限。首尾也计入上限，自适应选图直接输出；已移除末尾重复的全局去重步骤。
- 新任务和旧记录新建重跑默认采用自适应 15 张。API 仍支持显式 5 / 10，含义同样是上限，不能保证固定输出该张数。
- 没有 OCR 或模型判断，裁切线索不等于真正理解卡片是否完整。详细实现、能力边界与验收方法见 [自适应选图](docs/自适应选图.md)。

v1 尝试保留快速变化，v2 限制 25 张，v3 增加最终高度相似检查；5 / 10 张试跑记录是历史版本。v4～v4.2 曾复核补回前段淘汰帧，v4.3 已移除。真实业务覆盖仍以服务器上的实际样本反馈为准，不要求提供内部数据。

每次开始会分别保存两条链路的代码副本、代码校验值和默认参数，每题记录实际配置。过程图与最终图分开保存，旧结果不因修改代码而改变。远程视频每题只下载一次，供两条链路共用，各自独立抽帧。

## 耗时与计算复用

实验链路在一次抽帧内缓存特征，结束或失败后释放，不跨视频复用。内容特征最多 2048 项，小型布局/外壳特征另存最多 4096 项，文件标记最多 2048 项；字节相同的候选图可以复用结果。独立特征计算按 CPU 数限制为最多 8 项并行，首批过程图片复制最多并行 4 项，原输入顺序和图片编号保持不变。

局部检查最多预读 8 张图，活跃跟踪最多保留 32 份参考图，更早的内容仅留覆盖记录，跟踪参考范围不再向超过 4096 像素高扩展。旁路不重新读取视频，没有外部识别服务。

v4.7 局部模板搜索默认最多两个线程（`local_match_workers=2`），平台仍同时处理两题；低核服务器可在 `KeyframeConfig` 中设为 1。搜索峰值缓存最多 512 项，必须是完全相同的灰度输入；命中后仍执行原 RGB 严格核对。参考扩展后重新准备，任务结束或失败后释放。`local_fast_alignment=False`、`local_search_reuse=False`、`local_match_workers=1` 可用于关闭本轮提速做诊断，不改变筛选门槛。耗时和实际计算次数在每题 `local_analysis` 及 `process/trace.json` 中记录，不参与选帧。

v4.8 的“参考比较实际耗时”“背景核对”“其它准备”按实际经过时间拆分，三项合计约为局部总耗时（显示舍入可能有误差）。其它准备包含候选预读等待、裁图、特征计算、参考扩展和最后汇总；后台预读本身可能与当前帧处理重叠，不将其工作时间重复计入。“搜索位置累计”和“严格核对累计”是各搜索线程及主线程相应计算的用时相加，可能超过局部总耗时，不能直接相加或据此算占比；其中“图案搜索”是搜索位置内部的分项。宽度不同直接返回单独计数，不算完整搜索。

最慢候选按每帧局部处理的实际耗时排序，不含候选图片预读和最后的统一汇总；显示视频时间、帧号、每个比较区域的宽高、参与比较的最大参考区域以及实际比较次数。点击帧号查看原有图片和处理经过；此信息不判断关键帧价值。每题最多留 3 条，完成和失败都可保存已执行部分。新记录使用 `local_analysis.timing_schema=local-cost-v1`，详细字段在 `timing_breakdown` / `slowest_frames`；历史字段缺失不按零计入批次平均值，n 表示各项实际统计题数。

v4.8 与冻结的 v4.7 在五题真实候选上核对，覆盖关系、内容权重、质量分数、特征、代表替换、最终帧号及原比较次数均一致。本机这一轮局部检查平均 6.80 / 6.74 秒，未观察到明显的计时开销；单轮波动不作为提速结论，本版用于定位服务器慢样本。

v4.9 在相同五题真实候选上核对全部覆盖、质量、代表关系及最终帧号一致；单题顺序测量局部平均 6.77→4.49 秒，两题同时跑 7.43→5.28 秒。这里只是局部阶段，不包含前段取图、最后选图及过程保存，服务器数据仍需重跑验证。`KeyframeConfig.local_bounded_search=False` 可关闭 v4.9 的位置范围限制；投影缓存最多 8 张图，不增加依赖，全部逻辑仍在独立 `media.py` 中。

v4.10 再与冻结 v4.9 对照，同五题的覆盖、质量、代表关系、区域位置和最终帧号一致，局部平均 4.48→2.51 秒，两题并行 5.21→3.07 秒。参考的行积分只随活跃参考保留（最多 32 个参考，逐帧清理），扩展后失效，当前区域按需计算一次。没有接入收益很小的额外重复区域缓存，也没有跳过整张候选的局部分析。完整抽帧时间仍需服务器复测；方法、计数含义和试验记录见上面的说明。

本机五题真实候选回归（17 / 89 / 65 / 19 / 180 张）核对了全部覆盖关系、质量分数、内容权重、代表替换、特征和最终帧号，均与 v4.6 一致。顺序跑题时，局部检查平均从 9.23 秒降至 7.15 秒；两题同时跑时，本轮串行搜索 9.01 秒、双线程搜索 7.40 秒。这里只是“局部检查”分项，不是完整抽帧时间；不能据此保证服务器长尾降到 10 秒。内部视频、图片及测量详情只保存在忽略的本机目录。

场景变化点使用一次解码批量取图，仍按原三位小数时间规则取该时刻或之后的第一帧。批量失败或缺图回退到逐张方式；固定采样频率和变化检测未因提速而减少。

时间目标改为整批成功样本平均抽帧约 10 秒，包含中间图片和过程保存，不含下载、排队和视频内容校验。没有逐题超时强行取消或删图。使用 `python tools/benchmark_adaptive.py --workers 2` 复现固定 1–2 分钟组合，包含复杂长尾；测量结果与说明见 [自适应选图](docs/自适应选图.md)。此前 [5 / 10 张试跑](docs/5-10张试跑.md) 是历史测量。

耗时中的“视频准备 / 下载及等待”也包含两条链路共用下载时的等待；“核对视频内容”是读取视频计算内容标记。“保存过程图片与记录”单独计入实验链路分项，base 文件保持原样，只展示总体抽帧耗时。

过程记录只针对实际收集到的候选画面；没有抽到的时刻，需要结合原视频检查。原视频是否能在网页播放取决于浏览器支持的编码，不支持时可打开或下载查看。

## 同时处理本地视频与视频链接

`video_path` 可以填写服务器本地路径或 HTTP/HTTPS 视频链接，同一张表可以混用。远程视频先下载再抽帧，支持跳转和失败重试，不限制主机名。下载实现来自 auto_eval 的 `a5b0584` 更新（允许全部远程视频主机），没有调用模型。

上传表格不会同时上传电脑上的视频。服务器上的绝对视频路径直接读取，无需配置允许目录；相对路径默认从本项目查找，也支持 `../`。若现有相对路径以 auto_eval 目录为起点，可通过 `OPERATION_VIDEO_ROOTS` 增加查找目录；它仅用于查找，不限制绝对路径。

Linux：

```bash
export OPERATION_VIDEO_ROOTS=/path/to/auto_eval_agent
python app.py --host 0.0.0.0 --port 8503
```

PowerShell：

```powershell
$env:OPERATION_VIDEO_ROOTS = 'D:\wwc\project_4\auto_eval_agent'
python app.py --host 0.0.0.0 --port 8503
```

## 保存与重跑

结果都在项目 `runs/` 下，包括输入、进度、全部候选图、各步处理记录和最终图片；下载的视频保留供对照，用户原有的本地视频不复制、不删除。删除整个项目即可清除本项目实验数据。

刷新网页不影响批跑，服务重启后可查看保存结果。中断项可新建一次重跑，不自动续跑。
