# 抽帧实验台

从 auto_eval_agent 的现有抽帧方法开始，查看一批视频在每一步留下和丢弃的画面，帮助判断修改是否保住了重要信息。

仓库：<https://github.com/waldenZY/videosample_test>

## 当前状态

- 已建立本地仓库与远程 main 分支的跟踪配置；远程仓初始化时为空。
- `reference/media.py` 保存当前 auto_eval_agent 抽帧模块的原样副本。
- `reference/source.json` 记录来源、版本与文件校验值。
- 已实现文件上传、批跑、各阶段查看、淘汰原因追踪、相关图片与原视频对照。
- 每次可选只跑 base、只跑实验或两条都跑，查看各自步骤和结果，不做步骤对齐或差异对比。
- 第一版方案见 [docs/方案.md](docs/方案.md)。

原始副本用于核对初始结果。固定 base 不变，实验链路已开始尝试保留快速变化与短暂画面。

输入及抽帧前处理参考 auto_eval_agent，抽帧完成后进入查看页面，不继续评估。固定基线位于 `videosample/versions/base_media.py`，实验修改放在 `videosample/media.py`。定稿迁回时允许少量适配，去掉实验用过程记录与中间图片，保留正常抽帧输出。

## 启动

进入本项目目录，在 moto 环境运行（Python 3.10 或更新版本）：

```bash
conda activate moto
python -m pip install -r requirements.txt
python app.py --host 0.0.0.0 --port 8503
```

本机打开 <http://127.0.0.1:8503>；部署到服务器时，本地浏览器访问 `http://服务器地址:8503`。网页无需另行构建。FFmpeg 可使用系统安装或依赖中的 imageio-ffmpeg，首页会检查是否就绪。

## 使用

1. 上传现有 Excel、CSV 或 JSONL，预览样本、错误与提醒。
2. 勾选样本，选择只跑 base、只跑实验或两条都跑。实验输出可选“最多 5 张 / 最多 10 张”，默认 10 张；该设置只影响实验链路。新导入默认只跑实验，后台最多同时执行两项抽帧工作。
3. 只跑一条时直接查看该链路；两条都跑时通过链路按钮切换。点击样本就地展开本链路的步骤与图片，详情显示所用链路和版本。
4. 点击图片，查看其处理经过与相关画面；可以定位到原视频相应时刻。
5. 点击“新建一次重跑”复用输入，默认沿用上次运行方式和实验张数，也可重新选择。可以先跑 5 张，再新建一次重跑选 10 张，分别查看旧结果与新结果。旧版没有张数选项的记录，重跑默认选 10 张。
6. 展开样本中的“查看各阶段耗时”，查看视频准备、读取信息、视频内容校验和抽帧处理的耗时；实验链路还会列出取图、内容筛选、名额分配、去重与过程保存的分项。分项属于抽帧合计，不重复相加。旧结果不补造耗时数据，需重跑后查看。
7. “本次链路统计”分别展示各链路的平均每题总用时、平均抽帧用时、初始候选和最终输出的平均张数与总数。仅统计成功样本，不受列表筛选影响；每项 n 是实际有该项数据的题数，旧记录缺失的字段不按零计入。

初始候选数量指第一次筛选前收集的全部候选，含固定采样、场景变化及首尾帧，未去重；不是原视频的总帧数。每题总用时含视频准备与下载等待，不含线程池排队。总张数仅汇总本链路成功样本。

两条链路各自记录步骤，实验链路以后可以增删或重排步骤，不需要与 base 对应。一条链路失败不会阻止另一条完成。

## 固定 base 与后续实验

base 固定为复制时 auto_eval_agent `45dd11a` 的 `hybrid-state-v3.2.0`：选帧方法与默认参数相同，只增加实验用过程记录。本地路径允许读取项目目录外的视频是实验台外围适配，不改变抽帧方法。

`videosample/versions/base_media.py` 与 `base.json` 不再修改。以后在 `videosample/media.py` 中尝试新方法或参数，重启服务后只跑实验即可；需要基线时再选 base 或两条都跑。

当前实验版 `hybrid-state-exp-v3`：

- 固定采样从每秒 1 张增加到每秒 4 张，场景变化阈值从 0.06 调低到 0.02，变化事件的最小间隔从 0.8 秒缩短到 0.15 秒，给短卡片和连续操作更多进入候选的机会。
- 相近时刻先检查完整彩色画面，仅合并相似图片；每组限定在固定时间范围内，不再通过相邻关系把长时间候选串成一组。任务首帧与指定结束帧独立保留。
- 同页内部先按实际彩色内容分组，并检查局部区域的变化，为不同内容分别选择代表；较长时间出现的相近内容合并重复，不再只取页面首尾而丢掉中间卡片。
- 新增“合并重复内容”步骤：分配数量之前，将重复展示的相近内容合并，保留代表图与任务首尾位置。比较以固定参考图为准，避免连续小变化逐步漂移后全被并入同一组。
- 实验台每题可选最多 5 张或 10 张。先优先覆盖不同页面，再根据与已选图片的内容差异、局部变化和停留情况分配其余名额，首尾图片也占名额。时间分散不再作为主要排序依据，短暂画面和定时保护采样也不再无限豁免。数量分配发生在最后去重之前，不在输出时按顺序截断。独立模块的兼容默认值仍为 25，实验台将每次所选的 5 / 10 写入覆盖配置及每题实际配置。
- 最后新增全局高度相似检查：检查全部最终候选，不要求相邻、不限制时间间隔。完整彩色画面的整体差异、变化像素比例、局部区域和更小区域的差异均很低才合并，优先保留停留更充分的代表图；删除记录指向真正留下的图，并记录时间间隔和差异值。
- 不通过已经删除的图片串联相似关系。首帧及任务结束位置仍保留，相似时注明原因。最终去重后不补图凑数，因此简单视频可以少于 5 / 10 张。
- 若某张图在全局检查后保留，记录会给出最接近的已选对照图，以及哪些差异阻止了合并。先确认查看的是实验链路及新版本，再据此检查真实重复案例；不能把没有删图直接等同于去重未执行。

v1 提高了快速画面的覆盖，但短暂画面和保护采样过多时可能输出上百张；v2 提前合并重复内容并限制为 25 张；v3 在此基础上补充最终全局高度相似检查。被舍弃的内容会记录原因及相关的已选图；相近不等于业务信息完整覆盖。如果确有超过 25 种独立内容，不保证全部留下。

生成的短弹窗、短暂整页、连续切换、同页不同卡片、重复展示及大量动态画面均有测试。尚未用你此次反馈的真实样本复核；滚动文字的完整覆盖、很小的局部变化和自动任务结束判断仍需检查，未增加 OCR 或模型判断。

每次开始会分别保存两条链路的代码副本、代码校验值和默认参数，每题记录实际配置。过程图与最终图分开保存，旧结果不因修改代码而改变。远程视频每题只下载一次，供两条链路共用，各自独立抽帧。

## 耗时与计算复用

实验链路在一次抽帧内缓存图片特征，最多保存 512 项，结束或失败后释放，不跨视频复用。字节完全相同、位于不同路径的候选图也可复用特征，文件标记另外最多缓存 512 项；没有放宽图片相似判断。分配图片名额时继续使用已经算出的最近距离和对照图，避免为展示淘汰原因再比较一遍。

场景变化点改为一次解码批量取图，仍按原来的三位小数时间取该时刻或之后的第一帧；使用过滤脚本避免大量时间点超过 Windows 命令长度。批量取图失败或个别时间点缺图时回退到原逐张方式。固定采样仍为每秒 4 张，变化检测仍检查原视频，不为赶时间减少短暂变化进入候选的机会。base 保持原实现。

新的时间目标是每题抽帧处理在 6–7 秒以内：按“平均抽帧用时”和每题分项中的“抽帧处理合计”观察，包含实验台保存中间图片与记录的时间，不含下载、线程池排队和视频内容校验。它是性能目标，没有到时强行停止或删图；视频分辨率、变化频繁程度及服务器负载会影响实际耗时，尚不能保证所有视频都在 7 秒内。

本机模拟视频的具体测量和未达标案例见 [5 / 10 张试跑](docs/5-10张试跑.md)。

耗时中的“视频准备 / 下载及等待”也包含两条链路共用下载时的等待；“核对视频内容”是读取视频计算内容标记。“保存过程图片与记录”单独计入实验链路分项，base 文件保持原样，只展示总体抽帧耗时。

过程记录只针对实际收集到的候选画面；没有抽到的时刻，需要结合原视频检查。原视频是否能在网页播放取决于浏览器支持的编码，不支持时可打开或下载查看。

## 同时处理本地视频与视频链接

`video_path` 可以填写服务器本地路径或 HTTP/HTTPS 视频链接，同一张表可以混用。远程视频先下载再抽帧，支持跳转和失败重试，不限制主机名。下载实现来自 auto_eval 的 `a5b0584` 更新（允许全部远程视频主机），没有调用模型。

上传表格不会同时上传电脑上的视频。服务器上的绝对视频路径直接读取，无需配置允许目录；相对路径默认从本项目查找，也支持 `../`。若现有相对路径以 auto_eval 目录为起点，可通过 `OPERATION_VIDEO_ROOTS` 增加查找目录；它仅用于查找，不限制绝对路径。

Linux：

```bash
export OPERATION_VIDEO_ROOTS=/path/to/auto_eval_agent
python app.py --host 0.0.0.0 --port 8503
```

PowerShell：

```powershell
$env:OPERATION_VIDEO_ROOTS = 'D:\wwc\project_4\auto_eval_agent'
python app.py --host 0.0.0.0 --port 8503
```

## 保存与重跑

结果都在项目 `runs/` 下，包括输入、进度、全部候选图、各步处理记录和最终图片；下载的视频保留供对照，用户原有的本地视频不复制、不删除。删除整个项目即可清除本项目实验数据。

刷新网页不影响批跑，服务重启后可查看保存结果。中断项可新建一次重跑，不自动续跑。
